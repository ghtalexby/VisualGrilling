# Question preparation and more

- `{"type":"question", ...}`: prepare 2–4 realistic options for the user’s exact `question` text. Use `context.focus` (parent and ancestors), `related`, and project context; scan `context.questionTitles` and use `G node` only for plausible duplicate candidates. On similarity rejection, include `allowSimilar` in `question` only after reading the matching card and confirming a distinct question. Return `{"type":"question","id":"<request id>","token":"<event token>","question":{"why":"...","area":"...","options":["...","..."]}}`. Add `area` for a main question (`parentId:root`); children inherit it. Do not answer or grade the question. The server retains the submitted text, creates one card, and assigns the next main priority. Then return.
- `{"type":"more","token":"<event token>", ...}`: this is the compatibility event (the current UI uses Reread). Find zero to three useful new main questions absent from `mainQuestions`, never inventing questions for a quota, order by criticality, send `{"type":"more","token":"<event token>","questions":[...]}` using the init format, then return.
