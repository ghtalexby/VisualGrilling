# 4.5 Parallel maps (level 1 only)

Keep a served-map table: absolute maps root (`--dir`), `name` (null for legacy), selected language/locale option, background watch task id, preparation-running flag, and session-local `finished` flag (false for new or explicitly continued rows). These session flags are distinct from the persisted server `finished` field. Codex and level 0 remain one map per session.

- Starting a new grilling must leave other maps running. Select a new name, gather context, init, save useful changed notes, add its row and arm one watch.
- Exactly one watch per map. While map A is being graded, keep A unarmed and leave other watches running. Process events one at a time in notification order; other completions wait. Never prepare multiple events simultaneously.
- For parallel level 1 use `G watch --inbox` too: read the full inbox only when handling its event yourself. Follow the shared local result/preflight procedure. Short work lines contain `{type,id?,token?,name,language,characters,inbox,sections}`; expired lines also contain `name`, null for legacy. Plain watch also uses an inbox header above 20000 characters; `--inline` forces JSON. Match the line's name AND the completing task's root/table row before selecting command options; never route by remembered current page. Diagnose mismatches rather than applying to another map. Exit code 2 has no event line: use the task's table row.
- Chat commands in the user's language: “which grillings” runs `G list` and marks served maps; “continue <name>” runs `G start --continue` with its selected language, performs setup and arms a watch; “stop <name>” stops its task, settles or interrupts its preparation, runs `G stop`, and removes its row. Continuing an already served map must reuse its watch, not arm another. Ask which map an ambiguous request targets when several are served. Switching the browser page does not change dispatch routing.
- After any new finish completes, including failed finish, stop listening for that map at its persisted `actionQueue.paused` boundary. Save/report the outcome and requested report; leave its server readable. Later actions remain queued until explicit continuation. Do not drain them.
- On explicit continuation, reset the row's local finished flag and run `G start --continue` before arming or reusing its watch. The historical server `finished` flag and summary do not stop this continued cycle; only a new finish boundary or user Stop does. Do not reset state or call init.
- If the table is lost or unreliable (including after compaction), inspect the host's running background tasks and their command options before arming anything. Stop stale watch tasks and wait for their exit; do not interrupt another session's tasks. Recover which maps should be served from session/user context, asking if ambiguous. Resolve any active preparation before re-arming its map. Recover the session-local finish flag from the last continuation and applied finish in session context, not from server `finished`; ask if that lifecycle state is ambiguous. Rebuild the table and arm exactly one watch per intended map. Never arm without checking for an existing task.
